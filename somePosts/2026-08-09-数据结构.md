# 数据结构

**数据结构**是一门研究**非数值计算**（非结构化数据）的程序设计中计算机的**操作对象**以及它们之间的**关系**和**操作**的学科

学习数据结构以更有效使用计算机

数据（Data）

信息的载体，对客观事物符号化的表示，能够被计算机识别、存储和加工。有数值型、非数据型。

数据元素（Data element）和数据项

数据的基本单位，通常作为整体。也称记录、结点或顶点：“图”中的一个顶点。

数据元素由若干数据项构成，是构成数据元素不可分割的最小单位。

数据 > 数据元素 > 数据项

数据对象（Data Object）

性质相同的数据元素的集合，**是数据的一个子集**

整数数据对象集合N；字母字符数据对象集合C；学籍表也可看做一个数据对象

数据结构（Data Structure）

数据元素相互之间的关系称为结构。指相互之间存在一种或多种特定关系的数据元素集合。或者说，数据结构是带结构的数据元素的集合。

数据元素之间的逻辑关系称为逻辑结构。数据元素及其关系在计算机内存中的表示，称为数据的物理结构或数据的存储结构。数据的运算和实现，即对数据元素可以施加的操作以及这些操作在相应的存储结构上的实现。

逻辑结构与数据的存储无关，独立于计算机，是从具体问题抽象出来的数学模型。

物理结构（存储结构）是数据元素及其关系在计算机存储器中的结构（存储方式），是数据结构在计算机中的表示。

**逻辑结构与存储结构的关系**：存储结构是逻辑关系的映像与元素本身的映像。

> 这句话怎么理解呢？“映像”可以直接理解为“映射”或“具体实现”。更通俗地讲：映像就是把抽象的东西，变成计算机内存里实实在在能存放的东西。存储结构首先把数据元素真实地存进内存的某个单元里，这就是“元素本身的映像”;再把元素之间的关系也用内存的方式表示出来，这就是“逻辑关系的映像”。

逻辑结构是数据结构的抽象，存储结构是数据结构的实现。两者综合起来建立了数据元素之间的数据关系。

逻辑结构的种类

划分一

（1）线性结构

有且仅有一个开始和一个终端结点，并且所有结点都最多只有一个直接前趋和一个直接后继。

e.g.线性表、栈、队列、串

（2）非线性结构

一个结点可能有多个直接前趋和直接后继

e.g.树、图（人机对弈问题、最短路径）

划分二

（1）集合结构：结构中的数据元素之间除了同属于一个集合的关系外，无任何其他关系。

（2）线性结构：结构中的数据元素之间存在一对一的线性关系。

（3）树形结构：结构中的数据元素之间存在一对多的层次关系。

（4）图状结构或网状结构：结构中的数据元素之间存在着多对多的任意关系。

存储结构的种类

四种基本的存储结构：

- 顺序存储结构
  - 用一组连续的存储单元**依次**存储数据元素，数据元素之间的逻辑关系由元素的存储位置来表示。
  - C语言中用数组来实现顺序存储结构

- 链式存储结构
  - 用一组任意的存储单元存储数据元素，数据元素之间的逻辑关系用指针来表示

  - C语言中用指针来实现链式存储结构

- 索引存储结构
  - 在存储结点信息的同时，还建立附加的索引表。Index

  - 索引表中的每一项称为一个索引项

  - 索引项的一般形式是：（关键字，地址）

  - 关键字是能唯一标识一个结点的那些数据项

  - 若每个结点在索引表中都有一个索引项，则该索引表称之为稠密索引（Dense Index）。若一组结点在索引表中只对应一个索引项，则该索引表称之为稀疏索引（Sparse Index）

- 散列存储结构
  - 根据结点的关键字直接计算出该结点的存储地址。

数据类型和抽象数据类型

在使用高级程序设计语言编写程序时，必须对程序中出现的每个变量、常量或表达式，明确说明它们所属的数据类型。

一些最基本的数据结构可以用数据类型来实现，如数组、字符串等；

而另一些常用的数据结构，如栈、队列、树、图等，不能直接用数据类型来表示。

高级语言中的数据类型明显或隐含地规定了在程序执行期间变量和表达所有可能的取值范围，以及在这些数值范围上所允许进行的操作。

数据类型可以约束变量或常量的取值范围和操作。

数据类型 = 值的集合 + 值集合上的一组操作

抽象数据类型（**A**bstract **D**ata **T**ype，ADT）

指一个数学模型以及定义在此数学模型上的一组操作

不考虑计算机内的具体存储结构与运算的具体实现算法

抽象数据类型可用（D,S,P）三元组表示：

- D：数据对象

- S：D上的关系集

- P：对D的基本操作集合

  - List：存储一组特定数据类型的元素。能够根据他们在列表中的位置来读取里面存储的元素，而且也能够修改列表中特定位置的元素，能够存储任何数据类型的给定数量的元素。所以我们只是定义一个模型，可以用编程语言以多种方式去实现它。

  - 实现将是一些具体类型，而不是抽象数据类型

## Link List

上一个例子中，我们尝试使用数组实现动态列表，但是发现在存储使用方面并不有效。当我们使用数组时，我们需要理解链表的一些限制，以便更好地理解链表。

在计算机内存储中，每字节的内存都有一个地址。假设其从左边向右边延伸。

假设第一个地址（最左边）是200，它的右边是201。

内存是很重要的资源，几乎每个应用程序都会请求它。因此，计算机将这个管理内存的任务交给了一个叫内存管理器**Memory Manager**的成员<--它负责跟踪内存中哪些部分是空闲的，哪些部分是已被分配的。任何需要内存来存储数据的应用程序都需要与它交谈。

此时一个程序想在内存中存储一个整数，**小程**通过声明一个整数变量来与内存管理器沟通。

```c
int x;
```

Memory Manager看到之后，向这个请求分配了4个字节的内存。怎么分配呢？内存管理器在内存中寻找4个字节的空闲空间，并为变量X分配。内存块的地址是内存中第一个字节的地址，假设第一个字节的内存地址是217。所以变量x在217，内存管理器将这个信息传达给小程，小程就可以在这个变量中填入任何数据。

```c
int A[4];
```

现在小程需要存储一个整数列表，它认为这个列表中最多有4个整数，所以向内存管理器请求一个名为A的大小为4的整数数组。数组总是作为一个连续的内存块存储在内存中，所以内存管理器为数组A寻找一个16字节长的内存块，找到了，并分配这个块的起始地址201和结束地址216。

数组作为连续的内存空间，每当小程想要访问数组中的任何元素时，比如它尝试在数组的第4个元素中写入一些值`A[3] = 2;`,因为小程知道块A的起始地址201，所以201+3来计算`A[3]`的地址。

要访问数组中的任何元素，需要**constant time**，即应用程序可以在**常数时间**内访问数组中的任何元素。

假设当前的A是[6,4,4,2]，x是8，A和x首尾相连。小程此时想在数组中添加第5个元素，所以问内存管理器说想要扩展我的数组A，能做到吗？不行的！因为内存管理器在为数组分配内存时，并不期望小程会要求扩展。在一般情况下，A的右边还有空块的情况下，是OK的。但这里有一个变量X在A的旁边，所以不行。

那要怎么办？内存管理器说小程你告诉我要扩展的大小，我可以在某个新地址重新创建一个新块。我们将不得不把所有元素从先前的块复制到新块。这次新的地址是224，并且小程要求内存管理器释放先前的块，必须支付的代价是将所有元素、所有数组从先前的块复制到新块中。这次小程将数组保持得很大，以防出现相同的情况。

所以小程唯一的选择是将A创建为一个新的块，但仍感到不安。因为如果它没有使用巨大A的某些部分，就意味着内存被浪费了，而如果元素增加得过多，它又不得不创建一个新块，并复制所有元素。这个问题的解决方案是一个新的数据结构————链表。

> 别说，还真蛮清晰的。==\_== 现在终于知道从存储结构上来说数组的不足了。

我们来康康链表是怎么工作的。这是小程可以做的是，不再向内存管理器请求一个数组，一个巨大的连续内存块，而是可以一次请求**一个**数据单位，作为一个单独的请求。现在清理下刚才的内存，干净了。

假设小程要存储一个包含4个整数的列表，并一次请求一个单元，内存管理器告诉它在地址204获得这个4字节的块，小程用来存储6，再向内存管理器提出一个单独的请求来存储数字5，假设它获得从地址217开始的块来存储数字。因为每次发送的是单独的请求，所以有可能也有可能不会获得与数字6相邻的内存，内存中空余的位置有这么多，更大的可能性是他不会获得相邻的内存位置。接着小程分别为数字4和2发出单独的请求，假设在232和242获得这俩块。我们可以看到，小程并没有获得一个连续的内存块，而是获得了不相连的非连续内存块。除此之外，链表不可能不付出任何代价就能取得比数组更好的效果，我们需要以某种方式将这些块链接在一起。在数组中这很简单，我们可以通过块的起始位置和数组中元素的位置来计算其位置；在链表里我们需要知道这是第一个元素，这是第二个...以此类推。为了将他们连在一起，并存储位置信息，我们可以在每块中存储一些额外信息。比方说我们可以在每个块中有两部分：一个部分存储数据或值，另一部分存储下一个块的地址。

```c
[[6, 217], [5, 232], [4, 242], [2, 0]]  // 2后没有元素，可以设成0，0是无效地址，可以用来标记结尾
```

所以一次单独的请求实际上是小程在向内存管理器请求一个包含两部分内容的块。C中可以写成：

```c
Struct Node{
    int data;  // 4 bytes
    Node* next;  // 4 more bytes for pointer
}
```

链表的逻辑视图就是以上，数据存储在这些节点中，每个节点存储数据和到下一个节点的链接。第一个节点被称为头节点，我们保留的唯一信息是头节点的地址，头节点的地址可以让我们访问完整的列表；最后一个节点的地址是null或0。我们想遍历链表唯一的方法是从头开始，找到第一个节点，然后一个一个询问下去。之后的一切增删改操作都与调节节点指向地址有关。

与数组不同的是，**我们无法在常数时间内访问任何元素**，这是可想而知的。我们必须从头开始一个一个询问，因此访问元素所需的时间将于链表的大小成正比，操作的时间代价是O(n)。要插入时我们也需要遍历整个链表并到达那个特定位置，所以时间复杂度还是O(n)，唯一有变化的是，插入这个操作本身是常数级别的，我们不需要像在数组中那样进行所有的位移。同样道理的，删除操作也是O(n)。

相比数组我们可以发现，**没有内存未被使用**，但也用了一些额外的内存来存储地址。好处是可以随时进行增加或删除操作，而不再像数组中那样先猜测需要的大小。
